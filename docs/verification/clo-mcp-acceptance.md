## Boat 原生多色组导出基准

CLO 2026.1.382 通过官方 MCP 在空白工程创建了 Front、Back 和一组反向缝线。复制默认色组后得到 `Original` 和 `Alternate`，分别设为 `#990033` 和 `#245fdd`。原生 API 读回了两组独立 RGBA，保存时当前色组为索引 1。

`scene_export(path="colored.<ext>", colorways=true)` 的 `path` 保留请求值。官方 `result` 中的文件以色组顺序排列：

| 格式 | `result` 中的文件名 |
| --- | --- |
| OBJ | `colored_Original.obj`、`colored_Alternate.obj`、两份同序 `.mtl` |
| FBX | `colored_Original.fbx`、`colored_Alternate.fbx` |
| GLB | `colored_Original.glb`、`colored_Alternate.glb` |
| glTF | `colored_Original.gltf`、`colored_Alternate.gltf`、两份同序 `.bin` |

本例同样验证了 DXF 返回单一路径。同一工程的纸样 JSON 调用返回 `result: false`，导出条件待查。相同的裁片创建和反向缝合请求在 Rust 返回了相同的裁片索引、名称及缝组数。两端的缝组成员相同，自动组名不同。

两份官方归档传回后均已校验 SHA-256。Rust 按类型和字段名读取裁片、边界和网格后，成功恢复两片裁片、原名缝组及两个色组。ZPRJ 与 ZPAC 分别读回 52 和 36 个姿态顶点，零步调用保持坐标与拓扑。同一 ZPRJ 现场复开后，两端 9 个场景字段、缝组名称和成员、6 条边的端点与索引相同，边长偏差小于 0.001 mm。Rust 从每个色组的样卡读回各自的正面 RGBA，三参数 API 和保存重开后的 Python 调用通过。Rust 四种网格格式的双配色文件名与附属文件顺序匹配官方 MCP 返回。读取两端实际文件，每个文件均有 68 个三角面，正面 RGB 差小于 0.000001。GLB 与 glTF 的原生材质按官方样例输出线性色值，OBJ 与 FBX 保持原 RGB。Boat 的双配色贴图样例另用两张 16×16 PNG 验证。保存重开后，两端四种格式均保留各自的图像，八份实际文件的解码 RGBA 逐像素一致，有效 UV 边界差小于 0.00001。样例使用无偏移和旋转的正面贴图。另一次双配色实测对照了四种格式的法线图像，以及 glTF/GLB 的法线强度和 UV 重复比例。FBX 的透明度图可回读。OBJ 的粗糙度和透明度源 PNG 随文件输出，官方 MTL 未绑定这两个通道。官方对照确认，保存 ZPRJ 或 ZPAC 后，GLB/glTF 只导出当前色组，重新选中有效色组、调用 `UpdateColorways(true)` 或改色后恢复逐色组输出。Rust 实测复现保存和重新选择的顺序，正向越界索引和 `UpdateColorways(false)` 保持保存后的行为。复杂映射和其他通道仍待验。

用同一 ZPRJ 复跑时，Boat 官方端与 Rust 在重新选择索引 1 后，都按 `Original`、`Alternate` 输出两个 GLB。保存后两端都只输出一个 GLB、一份 glTF 加 BIN，OBJ 仍输出两个 OBJ 加两份 MTL。再次选择索引 1 后，两端都恢复两个 GLB。本轮对照了 MCP 返回的有序文件名，Rust 回归还检查了文件存在和 GLB 色值。复测将入口和文件分开控制。官方端对 ZPRJ 和 ZPAC 分别执行公开 `scene_open`、Python 默认选项及 Python 显式替换选项。六条路径在保存后都只输出一份 GLB，重新打开原输入后都输出两份，顺序为 `Original`、`Alternate`。用公开工具和 Python 重开刚保存的档案也同样恢复双份。Rust 回归逐条检查了公开和 Python 默认重开、当前色组及两组 RGBA。此前观测到的官方单份导出在本轮控制条件下未复现。另一次官方清场后首次导入 ZPAC 仍只输出单份，触发条件待查。

保存当前色组的跨端回开已验证。Rust 从三份官方归档切换索引 1 → 0，写出一份 ZPRJ 和两份 ZPAC。Boat CLO 2026.1.382 通过公开 `scene_open` 打开这三份输出，均读回索引 0、两组原始 RGBA、两片纸样、一组缝线和相同的面料记录。带贴图的 ZPAC 在官方 CLO 重开后导出 GLB，16×16 基础贴图的 256 个 RGBA 像素和原始素材及官方基准一致。Rust 回开还逐项对照了纸样、缝组和保存网格。Rust 回归验证了切回索引 1。

双配色改色的跨端回开已验证。Boat 官方 CLO 先改当前 `Alternate` 为 `#123456`，读回 `Original` 原色，再切到 `Original` 改为 `#a34429`。Rust 重放同一顺序，分别保存只改一组和改两组的 ZPRJ、ZPAC。官方 CLO 重开四份 Rust 归档，当前索引、两组 RGBA、纸样和缝组均与同阶段官方基准一致。带贴图的 ZPAC 重开后，两份实际 GLB 的 68 个三角面、基础色系数及 16×16 贴图的 256 个 RGBA 像素一致。共享样卡仍待验。

双配色基础贴图的替换和清除已通过 ZPAC 跨端回开。先替换当前 `Alternate` 的现有基础贴图并保存，再切到 `Original` 清除基础贴图并另存。官方 CLO 重开两份 Rust 归档，分别读回原活动索引 1 和 0。重开后两端四份 GLB 的贴图有无、基础色系数和每份 68 个三角面一致。三份带图 GLB 的 16×16 RGBA 均与官方基准逐像素一致，归档中的贴图原名也匹配。添加缺失的贴图槽及共享资产替换仍待实现。Rust 拒绝给缺失槽添加贴图时保留已有目标文件。
